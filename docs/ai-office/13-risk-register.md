# 13 — Risk Register

| # | Risk | Likelihood | Impact | Mitigation | Owner doc |
|---|---|---|---|---|---|
| 1 | Existing portfolio regresses during Office development | Medium | High | Phase-end regression checklist (build/typecheck/lint/visual) every phase, no exceptions | [10](./10-testing-strategy.md) §2.13, [12](./12-definition-of-done.md) §2 |
| 2 | `proxy.ts` (single, project-wide) misconfigured, adding latency/risk to public routes | Low | Medium | Tight matcher (`/office/:path*`), explicit test | [08](./08-security-plan.md) §2, [10](./10-testing-strategy.md) §2.4 |
| 3 | Budget hard cap has a logic gap that lets LIVE spend exceed $30/month | Low | High (real money) | Single enforcement point (`BudgetService.authorize()`), architectural import-graph test proving no other code path reaches a live adapter | [09](./09-budget-and-cost-controls.md) §2, [10](./10-testing-strategy.md) §2.5 |
| 4 | An agent output triggers a destructive/production/paid action without owner review | Low | High | Allowlist-only `permittedActions` per role; destructive/paid/production actions are structurally absent from every role's allowlist, not merely policy | [04](./04-agent-architecture.md) §2, [08](./08-security-plan.md) §9 |
| 5 | Session secret or provider API key leaks into logs, artifacts, or client bundle | Low | High | `server-only` imports, `redactSecrets()` helper, no secret ever in `messages_events`/`audit_log` payloads | [08](./08-security-plan.md) §6, §8 |
| 6 | Native SQLite dependency fails to build on the developer's Windows machine | Medium | Medium | Prefer `node:sqlite` if the local Node version supports it; otherwise pin a `better-sqlite3` version with known Windows prebuilds | [06](./06-data-model.md) §1, [11](./11-implementation-phases.md) Phase 3 |
| 7 | Claude (or any provider) pricing changes silently, making cost tracking inaccurate | Medium | Medium | Isolated `pricing.ts` table, flagged as an ongoing maintenance item (not "set once") | [09](./09-budget-and-cost-controls.md) §8 |
| 8 | Simulated-mode fixtures don't represent real agent failure modes, so Phase 8's first live run surfaces large gaps | Medium | Medium | Phase 8 is explicitly scoped to expect and absorb this; fixtures updated afterward | [11](./11-implementation-phases.md) Phase 8 |
| 9 | Orchestrator's rule-based role selection picks the wrong roles for an ambiguous idea | Medium | Low | Rules are a small, isolated, tunable table; worst case is an extra/missing role, correctable by the owner mid-project via manual task creation (a Phase 6+ nice-to-have, not blocking) | [05](./05-orchestration-workflow.md) §2 |
| 10 | A future `office.db` file accidentally gets committed/exposed despite being local-only in intent | Low | Medium | Already covered by existing `.gitignore` `*.sqlite`/`*.db` patterns — verify the chosen DB file path actually matches them in Phase 3 | [02](./02-current-portfolio-assessment.md) §9, [11](./11-implementation-phases.md) Phase 3 |
| 11 | Owner locked out (forgotten password) with no recovery flow in the local MVP | Medium | Low | Local-only recovery is a re-seed script (developer has filesystem access); acceptable for a single-user local tool, revisited before any deployment | [08](./08-security-plan.md) §11 |
| 12 | Scope creep — Office work drifts into refactoring existing portfolio code "while we're in there" | Medium | Medium | Phase Definition of Done explicitly requires touching only the listed files unless a documented need arises | [12](./12-definition-of-done.md) §2.6 |
| 13 | Durable Runner's SQLite lease claim has a race allowing two claims of the same task, or a crash leaves a task stuck (not silently lost, but not recoverable either) | Low | Medium | Atomic compare-and-swap claim (SQLite single-writer guarantee), startup crash-recovery sweep, explicit lease-atomicity and crash-recovery tests | [03](./03-system-architecture.md) §9.3, §9.6, [10](./10-testing-strategy.md) §2.14 |
| 14 | TypeScript strict mode + whole-repo `tsc` means an Office type error can fail the existing site's build | Medium | Low | Acceptable and intentional (forces correctness); mitigated by normal CI/build discipline, not a design flaw | [02](./02-current-portfolio-assessment.md) §13 |
| 15 | Artifact content stored inline as TEXT grows unwieldy once real (live-mode) code artifacts are produced | Medium | Low | Deferred externalization plan to a local filesystem path already designed, ready to switch to in Phase 7 | [06](./06-data-model.md) §5 |
| 16 | Durable Runner's in-process poll loop (Option A) starts twice under Next.js dev-mode hot-reload, causing duplicate/racing claim attempts | Medium | Low | Module-level singleton guard; functionally harmless even if it happened (the lease claim is still atomic — worst case is wasted polling, not duplicate execution), but flagged to avoid confusing logs/activity-feed noise during development | [03](./03-system-architecture.md) §9.7, [11](./11-implementation-phases.md) Phase 5 |
| 17 | `docs/ai-office/**` (now explicitly internal, [08](./08-security-plan.md) §12) is merged into `master` or deployed publicly before the exclusion mechanism/timing question is resolved | Low | Medium | Flagged as a required pre-merge decision, not merely a nice-to-have; constrained to a no-history-rewrite resolution | [08](./08-security-plan.md) §12, [14](./14-open-questions.md) §1 |
